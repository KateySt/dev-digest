# server/specs — feature specs

Index of feature/behavior specs for `server/` — "how X should work," written
before or alongside implementation. Not test files; server tests live in
`test/`, browser journeys in `../e2e/specs/`.

| Spec | Feature |
|------|---------|
| [`skills.md`](./skills.md) | Skill attachment, ordering, trust-by-source, versioning — **implemented** (extended by [`community-catalog.md`](./community-catalog.md)) |
| [`eval.md`](./eval.md) | Evals regression harness: cases seeded from accepted/dismissed findings (`must_find`/`must_not_flag`/manual) with frozen diff fragments, versioned background suite runs per agent, pooled file + line-overlap scoring, regression alert, run compare, Promote vN, skill links bumping agent version, FindingCard Reply → GitHub (Learn split out to a future spec); **amended 2026-10-06**; **amended 2026-10-07** (non-array `expected_output` → 422) — **draft** (case CRUD, single-case run, `scoreEvalCase` already built; client side: [`../../client/specs/agent-evals.md`](../../client/specs/agent-evals.md)) |
| [`skill-evals.md`](./skill-evals.md) | Skill evals: versioned background suite runs per skill (isolated: baseline prompt + only the skill + `skill_eval` model, provider/model recorded), draft runs of unsaved text (latest only, never in history), history + regression alert with "model changed", compare + Promote via Restore, cross-skill dashboard + Run all skills, finding → skill-targeted case (per-target 409), scan-gated runs, cascade on skill delete, old synchronous run-all removed — **draft**, server implemented, AC-38 manual pending (client side: [`../../client/specs/skill-evals.md`](../../client/specs/skill-evals.md)) |
| [`ci.md`](./ci.md) | Publish/re-publish idempotency, skills-as-bodies config, no runner yet |
| [`project-context.md`](./project-context.md) | Project Context: markdown doc discovery, per-agent/per-skill attachment + order, token counts, run-time injection into the `## Project context` slot; **amended 2026-10-07** (symlink refusal, per-document size cap, synchronous 409 `project_context_blocked` + persisted reason, atomic serialized set replace, stub-LLM AC-29) — **draft** (client side: [`../../client/specs/project-context.md`](../../client/specs/project-context.md)) |
| [`pr-triage-queue.md`](./pr-triage-queue.md) | Bulk review trigger over a repo's `needs_review` set: batch cap, in-flight skip, bounded parallelism, independent per-PR failure, cost estimate, cached blast size on the PR list; **amended 2026-10-07** (concurrent-request safety, per-PR start-failure isolation, single-PR 409 `review_in_progress`) — **draft** (client side: [`../../client/specs/pr-triage-queue.md`](../../client/specs/pr-triage-queue.md)) |
| [`community-catalog.md`](./community-catalog.md) | Community skill catalog: live GitHub-sourced catalog replacing the fixture, folder-per-topic layout contract, tag slugs replacing the single `lang` field, additive nullable `repo_id` project scoping, language-matched suggestions, one-request browsing budget with honest degradation; **amended 2026-10-02** with an opt-in project filter on the skills listing (default scope unchanged) and post-creation reassignment of a skill's project, in any direction including back to global; **amended 2026-10-07** (create-time `repo_id` ownership, UUID-only `repo_id` → 422, raw-host entry bodies, per-entry body-failure fallback, unavailable only on tree failure, in-flight population dedup) — **draft** (extends [`skills.md`](./skills.md); client side: [`../../client/specs/community-catalog.md`](../../client/specs/community-catalog.md)) |
| [`onboarding-tour.md`](./onboarding-tour.md) | Onboarding Tour: deterministic `repo-intel` fact collection, PageRank-ordered reading path, commands derived from real repo files, exactly one structured LLM call, per-repo cached tour, degraded skeleton on partial index or model failure; **amended 2026-10-07** (boot reaping of orphaned jobs, capped repo reported `partial` with honest counts, timeout skeleton persisted within the job deadline) — **draft** (client side: [`../../client/specs/onboarding-tour.md`](../../client/specs/onboarding-tour.md)) |
| [`multi-agent-review.md`](./multi-agent-review.md) | Multi-Agent Review: `agentIds` on `POST /pulls/:id/review` creating a parent `multi_agent_runs` row with linked agent runs, one server-wide shared queue (`REVIEW_CONCURRENCY`, default 3) with `queued` status + queue position for every agent run, diff/intent prepared once, per-agent failure isolation, `GET /multi-agent-runs/:id` results with live columns and honest totals, deterministic on-read finding groups (file + ±3 lines + category/title overlap coefficient, deterministic union-find that never joins two findings of one agent) and disagreement rows flagging coverage gaps and severity splits as conflicts, multi-run "Cancel all", structured grounding drops in the trace, per-agent estimates, "1 vs 3" Measurements table — **draft** (client side: [`../../client/specs/multi-agent-review.md`](../../client/specs/multi-agent-review.md)) |
