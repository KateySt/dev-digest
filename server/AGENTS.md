# server/ — @devdigest/api

Full picture: README.md (stack, DI/request-flow diagram, API map, env vars) —
read it first.

## Stack

Fastify 5 + Drizzle ORM + Postgres/pgvector. Zod contracts from
`src/vendor/shared` double as route schemas (`fastify-type-provider-zod`).

## Commands

`pnpm dev` (:3001) · `pnpm test` (unit+integration) ·
`pnpm exec vitest run --exclude '**/*.it.test.ts'` (unit only, no Docker) ·
`pnpm db:migrate` · `pnpm db:seed` · `pnpm typecheck`

## Where things live

- `src/modules/<name>/` — one Fastify plugin per feature (routes + service),
  registered in `src/modules/index.ts`
- `src/adapters/` — ports behind the DI container (llm, github, git,
  astgrep, secrets, …); swapped for mocks in tests via `src/adapters/mocks.ts`
- `src/db/schema/` + `src/db/migrations/` — Drizzle schema and generated SQL
- `src/platform/container.ts` — the DI container
- `src/vendor/shared` — vendored `@devdigest/shared` contracts (do not edit
  here — see root `AGENTS.md`)

## Non-default conventions

- Routes validate `params`/`body` with zod schemas — never hand-roll
  `Schema.parse(req.body)` in a handler.
- A DB-backed test **must** be named `*.it.test.ts` (testcontainers Postgres)
  or the unit/integration split breaks.
- Secrets never go through `AppConfig` — always through `SecretsProvider`
  (`~/.devdigest/secrets.json`, `process.env` fallback).

## Naming conventions

- Each `src/modules/<name>/` uses fixed, role-based filenames —
  `routes.ts`, `service.ts`, `repository.ts`, `constants.ts`, `helpers.ts` —
  not domain-specific names. Follow the pattern when adding a module.

## Do-not-touch

- `src/db/migrations/*.sql` — generated by `pnpm db:generate` (drizzle-kit).
  Never hand-edit a migration that's already committed/applied; create a new
  one instead.
