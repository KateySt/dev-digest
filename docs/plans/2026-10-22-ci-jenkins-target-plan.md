## Decisions (confirmed by the user 2026-10-22)

- **Q1** — URL + username live in a new table `ci_jenkins_connections` (`id, workspace_id, repo, url, username, created_at, updated_at`, unique `(workspace_id, repo)`). Token only in `SecretsProvider` under `jenkins_api_token:<workspaceId>:<owner/name lowercased>`. S-AC-85 lists table rows and `secrets.get`s each token.
- **Q2** — `job_name`, both credential IDs and `agent_label` are **repo-wide**: a Jenkins export writes the request's values into every agent stage and updates those columns on every Jenkins installation of the repo; each peer keeps its own `triggers` (S-AC-50). Preview warns when values differ from stored peers ("changes job/credential settings for N other agents").
- **Q3** — `ci_server_url = null` → no mismatch check; sync uses the repo's current connection.
- **Q4** — CI Runs "Re-export" navigates to `/agents?agent=<agent_id>&tab=ci&reexport=<installation_id>`; CiTab opens the wizard pre-filled.
- **Q5** — a) `agent_label='any'` → `agent any`, else `agent { label '<expr>' }`; b) `jenkinsfile` with target `gha` → 422; c) changing a credential ID or label after a manual Jenkinsfile edit discards the edit with the C-AC-18 notice (job name doesn't); d) `RUNNER_VERSION` '2'→'3'; e) `redirect: 'manual'`, same-origin ≤3 hops, cross-origin → `jenkins_unreachable`; f) `CiExportInput.triggers` default unchanged, client always sends explicit triggers for Jenkins; g) CI Runs sync errors come from the latest sync result (gone on reload), CI tab row shows persisted `last_sync_error`.
- No new automated tests; triggers never flag "out of date"; Jenkins connection is per repo (dialog), token only via SecretsProvider.

## Architectural constraints

- **Isolation.** Main checkout holds another session's uncommitted doc-sync work (`0030_doc_sync.sql`, `meta/0030_snapshot.json`, `_journal.json`, `schema.ts`, `schema/repos.ts`, `modules/index.ts`, both `vendor/shared/index.ts`, client SettingsView). Work only in this worktree; never stage anything in the main checkout. Do not touch `db/schema.ts`, `modules/index.ts`, `vendor/shared/index.ts`, `messages/en/settings.json`, `lib/hooks/index.ts`, SettingsView.
- **Migrations.** Generate with drizzle-kit only, one `--> statement-breakpoint` per statement. Run against a separate DB, never a shared one. Drizzle skips out-of-order migrations silently: whichever of doc-sync / this branch merges second deletes its own migration SQL + snapshot + journal entry, rebases, and re-runs `db:generate`. Put this in the PR description.
- **Local Postgres.** Port 5432 is occupied by an unrelated container (`upwork-pg`); `devdigest-postgres` does not exist. Use a dedicated `pgvector/pgvector:pg16` container for this branch on another port (e.g. 5544).
- **Onion (server).** Ports in `vendor/shared/adapters.ts` (`JenkinsClient`, `SecretsProvider.delete?`, `GitHubClient.listPullRequestCommitShas`). Adapter `server/src/adapters/jenkins/` + mock in `adapters/mocks.ts`. Only `Container` constructs it, via a `jenkins(params)` factory with an override slot. `ci/service.ts` imports no Drizzle, no `fetch`, no concrete adapter. `ci/targets/` = pure generators behind `CiTargetGenerator` (gha, jenkins). `ci/sources/` = ring-1 sync behind `CiRunSource` (gha, jenkins). `repository.ts` Drizzle-only, `routes.ts` thin with zod schemas.
- **Client.** Dialog in `src/components/jenkins-connection-dialog/` (2+ consumers), code→hint mapping in `src/lib/ci-sync-errors.ts`, everything else colocated `_components/<Name>/`. `@/` imports, Tailwind tokens. Long URLs/IDs/messages wrap (`wrap-anywhere break-words min-w-0`, `minmax(0,1fr)`).
- **Vendored shared.** `contracts/eval-ci.ts` and `adapters.ts` are byte-identical in both trees today: apply the same edit to both, diff just those files.
- **Runner bundle.** `agent-runner/bundle/runner.mjs` regenerated by the build only.
