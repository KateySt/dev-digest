## Architectural constraints
- **Onion (`onion-architecture`):**
  - Scoring and pooled aggregation are ring-0 → `reviewer-core/src/output/`.
  - Server-only pure logic → `modules/eval/helpers.ts`: hunk filter + unified-text serializer, kebab name, input fingerprint (`node:crypto` sha256 of canonical JSON), regression-alert builder, compare flags.
  - Repositories = data access only. "Already running", "no cases", "missing skills" decisions live in `service.ts`.
  - Routes validate `params`/`body`/`querystring` with zod; never `Schema.parse(req.body)` by hand.
  - Reply uses the `GitHubClient` port via `container.github()` (same path as `POST /pulls/:id/comments`); never import `adapters/github/octokit.ts` from a service.
- **Cross-module data:** eval module's finding → review → PR → pr_files lookup in **`modules/eval/repository.ts`** (read-only joins). Reviews module's `eval_case_id` lookup in `reviews/repository.ts`.
- **DB-enforced invariants:** partial unique index on `eval_suite_runs(agent_id) WHERE status='running'` (S-AC-20; catch unique violation → 409). Unique index on `eval_cases(source_finding_id)` (S-AC-7). Promote (S-AC-15) and link-change bump (S-AC-13) each in **one transaction** producing exactly one new version.
- **Migration:** additive. `pnpm db:generate` (drizzle-kit); never hand-edit committed migrations `0000`–`0019`. Apply by hand with `pnpm db:migrate`. Existing `eval_runs` rows stay valid with `suite_run_id = NULL`. Proposed shape (implementer decides exact names):
  - `eval_cases`: `kind` must_find|must_not_flag NOT NULL default must_find; `source` manual|finding_accepted|finding_dismissed NOT NULL default manual; `source_finding_id` uuid FK → findings ON DELETE SET NULL, unique where not null; `created_at`.
  - new `eval_suite_runs`: `id`, `workspace_id`, `agent_id` FK → agents ON DELETE CASCADE, `agent_version` int, `status` running|completed|failed, `failure_reason`, `started_at`, `finished_at`, `cases_total`, `cases_done`, nullable `recall`/`precision`/`citation_accuracy`, `passed_count`, `evaluated_count`, `errored_count`, `duration_ms`, nullable `cost_usd`; index `(agent_id, started_at desc)`.
  - `eval_runs`: `suite_run_id` FK → eval_suite_runs ON DELETE CASCADE nullable; `status` ok|errored + `error`; `input_fingerprint`; raw pooling counts `expected_total`, `matched`, `grounded_total`, `noise`, `kept`, `dropped`.
  - `findings`: `reply_url` text, `replied_at` timestamptz.
- **Do-not-touch:** `server/src/vendor/shared` and `client/src/vendor/shared` edited **by hand, identically, in both trees**. `client/src/vendor/ui` — only the approved Sparkline single-point fix. Never hand-edit lock files. No new npm dependency.
- **Client placement (`react-project-structure`):** thin `page.tsx` delegating to colocated `_components/<Name>/`; hooks in `src/lib/hooks/`; UI used by ≥2 eval screens → `src/components/eval-metrics/`; pure logic → `src/lib/eval.ts`; `@/` alias imports only; all strings via next-intl, each screen its own `messages/en/<ns>.json` namespace.
