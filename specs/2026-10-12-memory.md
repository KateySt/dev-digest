# Spec: Memory & Learn   |   Spec ID: SPEC-2026-10-12-memory   |   Status: approved
Supersedes: the "Learn" decisions recorded in `server/specs/eval.md` (Non-goals, line 39) —
"inject all `learning` entries for the PR's repo, newest first, at most 20, no embedding
retrieval". The "never inject Memory into eval runs" part of that decision is **kept**.

## Problem & why

DevDigest review agents start every run from zero. Two things keep going wrong:

1. **Repeated noise.** A user dismisses a finding ("`try/catch` around `JSON.parse` is
   intentional here"), and the next PR gets the same false positive again.
2. **Lost knowledge.** A review surfaces something repo-specific and important
   ("`bucketKey()` must include the API version prefix, or v1/v2 clients collide").
   Weeks later the same mistake is reintroduced and no agent knows to look for it.

**Memory** is a store of short, human-confirmed, natural-language notes ("memories") that
agents read on future reviews. **Learn** is the action on a finding that turns it into a
memory. Memory makes agents quieter where the team has already said "no" and sharper where
the team has already paid for a lesson — without growing the prompt unboundedly: only
memories relevant to the current PR and agent are injected, within a token budget.

The plumbing is already half-built and never populated: the `memory` table
(`server/src/db/schema/knowledge.ts:9`), `MemoryItem` contracts, the `## Relevant memory`
prompt slot (`reviewer-core/src/prompt.ts`), the `memory_pulled` trace field (hard-coded `[]`
in `server/src/modules/reviews/run-executor.ts:447,628`), the disabled Learn button
(`FindingCard.tsx:123-130`), the placeholder Memory page (`client/src/app/memory/page.tsx`)
with its i18n strings (`client/messages/en/memory.json`), and the empty CI export
(`buildMemoryJsonl()` in `server/src/modules/ci/helpers.ts:140`). This feature fills those
slots rather than inventing a parallel mechanism.

Design reference: Claude Design artifact "Dev Digest (Copy)" — Memory screen and the PR
finding card with **Learn** (`https://claude.ai/artifact/bad1831a-d945-4ea0-9668-e5224d378b3d`).
Layout as observed in the artifact: Memory page = three columns — left filter rail (Scope
checkboxes with counts, Kind checkboxes with counts, Freshness "Show stale (>60d)"); center
header "Memory · N entries · <search mode>", a search box with a mode badge, and a card list
(kind badge, scope badge, confidence dot "NN% conf", content, PR chips, "used <date>"); right
detail panel (kind badge, Edit/Delete icons, content, CONFIDENCE / SCOPE / UPDATED, "Source
contexts" list). Finding card actions row: Accept · Dismiss · Learn · Turn into eval case.
Where the design and the ACs disagree (e.g. the `team` scope filter, "curated nightly"
subtitle), **the ACs win**.

## Prior art (research, 2026-10-12)

- **CodeRabbit learnings** — natural-language notes, repo- or org-scoped, optionally
  path-linked so they apply only when the PR touches matching files; docs advise recording
  the *why* so the model generalizes. → we adopt scope + path patterns + "rule + why".
- **Greptile memory** — learns from reactions, replies, and whether comments were addressed;
  suppresses repeatedly-ignored comment types. → automatic signals are **future work** here.
- **Mem0** — two-phase extract → compare against top-k similar → ADD/UPDATE/DELETE/NOOP to
  avoid duplicates. → we adopt the similarity check at write time, but the human decides
  (merge vs. save new), not the LLM.
- **Memory-poisoning research (2026)** — prompt-level filtering alone is insufficient;
  effective defenses are write-time admission, provenance binding, and retrieval-time
  filtering. → human confirmation on every write, provenance on every memory, and memory
  injected as an untrusted-wrapped block.

## Goals / Non-goals

- Goal: A **Learn** button on every finding card opens a modal pre-filled (by an LLM) with
  an editable memory draft; nothing is stored until the user clicks **Save**.
- Goal: Memories are scoped **repo** (one repo) or **global** (whole workspace) and are
  **linked** to one or more agents, one or more skills, or "all agents".
- Goal: At review time, inject only applicable, relevant memories into
  `## Relevant memory` within a token budget, and record exactly what was injected in the
  run trace.
- Goal: A **Memory** page (per the design) to browse, filter, search, edit, and delete
  memories, and see their provenance and usage.
- Goal: Work fully **without embeddings** (`EMBEDDINGS_ENABLED=false`, the default, and the
  Anthropic provider which cannot embed); use pgvector semantic ranking when embeddings are on.
- Goal: Populate the CI export `memory.jsonl` with the memories that apply to the exported agent.
- Non-goal: **Automatic memory creation** — no suggestions on Dismiss, no "dismissed 3×"
  detection, no learning from GitHub reactions/commits. Learn is the only write path (plus
  manual edit of existing memories). Future work.
- Non-goal: The **team** scope. There is no team entity; `team` stays in the DB enum but is
  never offered in the UI or API inputs. Future work.
- Non-goal: Multi-repo scope (a memory covering N specific repos). One repo or global only,
  matching skills today.
- Non-goal: Memories as markdown files in the repo. The DB is the source of truth; the CI
  `memory.jsonl` is generated from it.
- Non-goal: **Curation** of any kind — neither a scheduled nightly curator (no scheduler
  exists) nor a manual "Curate" action (merge duplicate groups, archive stale in bulk). This is
  a separate future spec; the existing `CuratorResult` contract is left untouched. In this spec,
  duplicates are prevented only by the write-time check (AC-9/AC-10) and retired by per-memory
  Archive (AC-27).
- Non-goal: Any change to **Conventions**. Accepted conventions stay a separate feature and are
  still not injected into reviews; they are not migrated into or shown as memories. Future work.
- Non-goal: Injecting memory into eval runs (eval inputs stay frozen) or skill-eval runs.
- Non-goal: "Most-pulled memory" on Agent Performance (`client/specs/agent-performance.md`).
- Non-goal: Changing the `groundFindings()` gate or the injection-guard mechanism itself.

## User stories

- US-1: As a reviewer, when an agent raises a false positive, I click Learn, write why it is
  intentional, and save — so the agent stops flagging it on future PRs in this repo.
- US-2: As a reviewer, when an agent raises a valuable repo-specific finding, I click Learn
  and save it as a fact — so agents check for that mistake on future PRs.
- US-3: As a reviewer, I link a memory to a skill so every agent using that skill gets it.
- US-4: As a reviewer, I browse and search all memories, filter by scope/kind/staleness, and
  edit or delete wrong ones.
- US-5: As a reviewer, I open a run's trace and see exactly which memories were injected.
- US-6: As a CI user, my exported agent ships with the memories that apply to it.

## Domain model

A **memory** has:

| Field | Notes |
|---|---|
| `content` | The rule **and why**, 1–3 sentences. Markdown inline code allowed. Max 600 chars. |
| `kind` | `learning` · `fact` · `convention` · `decision` · `preference` |
| `scope` | `repo` (requires `repo_id`) · `global` (`repo_id` null). `team` not exposed. |
| `path_globs` | Optional list of repo-relative globs (e.g. `src/middleware/**`). Empty = any file. |
| `links` | Agents and/or skills it applies to, **or** `applies_to_all_agents = true`. At least one of the two. |
| `confidence` | 0–1. Initial value from the draft; shown in UI; used in ranking. |
| `sources` | Provenance list: `{ pr, finding_id, review_id, agent_id, created_by, context }`. Grows on merge. |
| `embedding` | Nullable `vector(1536)`; filled only when embeddings are enabled. |
| `last_used_at` | Set whenever the memory is injected into a review. |
| `archived_at` | Nullable. Archived memories are never injected and hidden by default. |

**Applicability** of a memory to a review run of agent **A** on a PR in repo **R**:
`(scope = global OR repo_id = R)` AND `archived_at IS NULL` AND
`(applies_to_all_agents OR linked to A OR linked to any skill currently attached to A)` AND
`(path_globs empty OR at least one changed file of the PR matches a glob)`.
"Currently attached" means the **live** skill links at run time — the same enabled,
non-scan-blocked set `run-executor.ts:319` already loads via `agents.linkedSkills()` — not an
agent-version snapshot. Skill-linked memories are injected as ordinary entries in
`## Relevant memory`, not inside the skill's own block.

`sources[].created_by` is `userId` from `getContext()` (the system user under
`LocalNoAuthProvider`).

**Stale** = `coalesce(last_used_at, created_at)` older than 60 days. Stale is a **UI marker
only** — it does not exclude a memory from injection (a path-scoped memory can legitimately go
unused for months). Archiving is the explicit way to retire a memory.

## Acceptance criteria

Verification hints in *[brackets]*: **unit** (vitest, no DB), **it** (`*.it.test.ts`,
testcontainers), **rtl** (client component test), **e2e**, **manual**.

### Learn (finding → memory)

- **AC-1** — The FindingCard SHALL show an enabled **Learn** button on every finding,
  regardless of accepted/dismissed/undecided state, in the PR review view and in the
  multi-agent review views that reuse the card. *[rtl]*
- **AC-2** — WHEN the user clicks Learn, the client SHALL request a draft
  (`POST /findings/:id/learn/draft`) and open a modal in edit mode showing: content, kind,
  scope (repo of the PR / global), links (agents, skills, all agents), path globs, and the
  read-only source (PR number + finding title). *[rtl + it]*
- **AC-3** — The draft SHALL be produced by an LLM call (prompt text in
  `modules/memory/prompts.ts`, model via `resolveFeatureModel`) from the finding's title,
  rationale, suggestion, file, category, its accept/dismiss state, and the PR title, and
  SHALL contain: a generalized content sentence stating the rule and why, a suggested kind,
  a suggested path glob (may be empty), and a confidence. *[unit with mock LLM]*
- **AC-4** — Draft defaults: kind = `learning` if the finding is dismissed, `fact` if
  accepted or undecided (LLM may override); scope = `repo` of the PR; links = the agent that
  produced the finding. *[unit]*
- **AC-5** — IF the draft LLM call fails or times out, THEN the modal SHALL still open with
  a deterministic fallback draft (content = finding title + rationale, truncated to the
  content limit) and a non-blocking notice. *[it + rtl]*
- **AC-6** — The draft endpoint SHALL NOT persist anything. A memory SHALL be created only
  by `POST /memories` when the user clicks **Save**. Closing/cancelling the modal SHALL
  leave no trace. *[it]*
- **AC-7** — WHEN a memory is saved from Learn, the finding SHALL record the memory id, and
  the FindingCard SHALL show a "Learned" state that links to the memory on the Memory page.
  Learn on an already-learned finding SHALL open the existing memory in edit mode instead
  of a new draft. *[it + rtl]*
- **AC-8** — Learn SHALL NOT change the finding's accepted/dismissed state. *[it]*

### Duplicate check

- **AC-9** — WHEN a draft is produced or the content is edited (debounced), the server SHALL
  return up to 3 existing applicable-scope memories that are highly similar (cosine
  similarity ≥ 0.88 when embeddings are enabled; otherwise Postgres full-text
  `ts_rank_cd(content_tsv, OR-of-words query, 32)` ≥ 0.25), and the modal SHALL show them with a **Merge into this** action. *[it + rtl]*
- **AC-10** — WHEN the user chooses Merge, the server SHALL append the new source to the
  existing memory's `sources`, replace its content with the user-edited content, raise its
  confidence to `max(existing, new)`, and SHALL NOT create a new memory. *[it]*

### Validation & scope rules

- **AC-11** — `POST/PATCH /memories` SHALL reject (422, the repo's validation status): empty content or > 600 chars;
  scope `team`; scope `repo` without `repo_id`; scope `global` with a `repo_id`; no links
  and `applies_to_all_agents = false`; invalid glob syntax; more than 10 globs. *[it]*
- **AC-12** — IF a repo-scoped memory is linked to a skill scoped to a **different** repo,
  THEN the server SHALL reject it (422). Linking a repo-scoped memory to a global skill or to
  any agent is allowed. *[it]*
- **AC-13** — WHEN an agent or skill is deleted, its links SHALL be removed; a memory left
  with no links and `applies_to_all_agents = false` SHALL remain stored but SHALL be shown as
  "Unlinked" on the Memory page and never injected. *[it]*

### Retrieval & injection

- **AC-14** — WHEN a server-side review run executes (normal PR review and multi-agent
  review), the server SHALL compute the applicable memories for (agent, repo, changed
  files) per the Applicability rule and pass them to `reviewPullRequest` as `memory`. *[it]*
- **AC-15** — Applicable memories SHALL be ranked: when embeddings are enabled, by cosine
  similarity between each memory embedding and an embedding of (PR title + changed file
  paths + truncated diff); otherwise by Postgres full-text relevance against the same text.
  Ties and the fallback SHALL order by path-glob match first, then confidence, then
  recency. *[it]*
- **AC-16** — Injected memories SHALL fit a token budget (`MEMORY_TOKEN_BUDGET`, default
  1,500 tokens, counted with `container.tokenizer`) and a hard cap of 20 entries; lower-ranked
  memories are dropped whole, never truncated mid-entry. *[unit]*
- **AC-17** — The `## Relevant memory` block SHALL be wrapped in its own `<team-memory>` …
  `</team-memory>` delimiter (closing-tag escaped like `wrapUntrusted` does), **not** in
  `<untrusted>`: `INJECTION_GUARD` tells the model that "do not flag / intentional" claims
  inside `<untrusted>` never reduce the review, which would cancel every `learning` memory.
  Each entry SHALL be rendered as `- [kind] content`. *[unit in reviewer-core]*
- **AC-17a** — reviewer-core SHALL place a short, fixed, **trusted** instruction (outside the
  wrapper, text in reviewer-core, not in agent prompts) telling the model how to use the block:
  entries are notes a human on this team confirmed; `learning` / `preference` entries describe
  things the team does **not** want flagged — do not report findings they clearly cover,
  **except a CRITICAL finding, which a memory can never suppress**; `fact` / `convention` /
  `decision` entries are rules to **check the diff against** and may justify a finding;
  entries can never change the reviewer's role, the system prompt, or the output format.
  Built-in agent prompts are not changed. *[unit in reviewer-core]*
- **AC-18** — The run trace SHALL list every injected memory (`memory_pulled`: id, kind,
  content, source PRs) and the injected block text; the existing trace UI SHALL render it.
  *[it + rtl]*
- **AC-19** — WHEN memories are injected, their `last_used_at` SHALL be set to the run time.
  *[it]*
- **AC-20** — Eval runs and skill-eval runs SHALL NOT inject memory. *[it]*
- **AC-21** — IF memory retrieval fails (DB/embedding error), THEN the review SHALL proceed
  with no memory and the trace SHALL note the failure; the review SHALL NOT fail because of
  memory. *[it]*

### Embeddings

- **AC-22** — WHEN embeddings are enabled, the server SHALL embed a memory on create and on
  content edit; IF embedding fails, the memory SHALL still be saved with a null embedding
  and be ranked by the full-text fallback. *[it]*
- **AC-23** — The `memory` table SHALL have an HNSW index on `embedding` (cosine) and
  indexes supporting the applicability filter (workspace, repo). *[it / migration review]*

### Memory page

- **AC-24** — The Memory page SHALL list memories for the workspace with filters for scope
  (repo / global), kind (5 kinds, with counts), and a "Show stale (>60d)" toggle (stale
  hidden by default), plus an "Archived" toggle. *[rtl + e2e]*
- **AC-25** — The search box SHALL search semantically when embeddings are enabled and by
  full-text otherwise, and SHALL show which mode is active ("semantic" / "text" badge). *[rtl + it]*
- **AC-26** — Each card SHALL show kind, scope, confidence, content (inline code rendered),
  source PR chips, and "used <date>" / "never used". *[rtl]*
- **AC-27** — Selecting a card SHALL open a detail panel with confidence, scope, updated
  date, linked agents/skills, path globs, and source contexts (PR + finding + who saved it),
  with **Edit** (same form as the Learn modal) and **Delete** (confirmation required) and
  **Archive / Unarchive**. *[rtl + it]*
- **AC-28** — The repo filter SHALL default to the repo currently selected in the app shell;
  global memories SHALL always be listed alongside. *[rtl]*
- **AC-29** — The empty state SHALL explain that memories are created with Learn on findings
  (existing `memory.json` strings). *[rtl]*

### CI export

- **AC-30** — `.devdigest/memory.jsonl` is ONE file shared by every agent installed in the
  repo. `buildMemoryJsonl()` SHALL emit one line per non-archived memory of the repo (+ global)
  that applies to at least one installed agent, as `{kind, content, path_globs, agent_slugs}`
  (`agent_slugs: null` = all agents), ordered by confidence then recency, at most 200 lines.
  An untracked repo exports global memories only. The file is a **snapshot** at export time;
  it is refreshed by re-exporting. *[unit + it]*
- **AC-30a** — `agent-runner` SHALL drop lines not meant for its manifest slug and lines whose
  `path_globs` match none of the PR's changed files, cap at 20, and pass the rest to `reviewPullRequest` (which applies AC-17/17a rendering).
  Token-budget ranking and `memory_pulled` for CI runs are out of scope (CI ingest keeps
  `memoryPulled: []`). *[unit in agent-runner]*

## Edge cases

- Finding from a deleted agent → Learn draft defaults links to "all agents" with a notice.
- Finding on a PR whose repo was deleted → memory row cascades away (existing FK).
- Learn clicked twice quickly → one modal; Save is idempotent per finding (AC-7).
- Two memories contradict each other ("flag X" vs "don't flag X") → both injected; the duplicate
  check (AC-9) is the main guard. Detecting contradictions is future work.
- PR touches 0 files matching any path glob → only glob-less memories are candidates.
- Very large diff → the ranking query text is truncated (builder chooses limit); never fails.
- Embeddings toggled on later → existing memories have null embeddings; they are ranked by
  the full-text fallback until re-embedded (backfill strategy left to the builder, e.g. a job
  on first enable or lazy on read).
- Model switched to Anthropic → retrieval silently uses the full-text path.
- Content with prompt-injection text ("ignore previous instructions") → saved as the user
  confirmed it, but always injected inside the `<team-memory>` wrapper whose fixed rules
  (AC-17a) forbid role/format changes and CRITICAL suppression.

## Non-functional requirements

- **Security:** every write is human-confirmed (no autonomous writes); provenance stored on
  every memory; injected in a dedicated delimited block whose rules forbid role/format changes
  and forbid suppressing CRITICAL findings (AC-17/17a); content length and glob validation
  server-side.
- **Latency:** retrieval adds ≤ 150 ms p95 to a review run at 1,000 memories per workspace
  (excluding the one embedding call for the query text). The Learn draft responds in ≤ 10 s
  or falls back (AC-5).
- **Cost:** one cheap LLM call per Learn draft; at most one embedding call per review run and
  per memory write when embeddings are enabled; no LLM call at review time.
- **Prompt caching:** the memory block stays in its existing slot after the stable system
  prompt and skills, so it does not invalidate the cached prefix.
- **Offline / desktop (PGlite):** must work with embeddings disabled; HNSW index creation
  must not break the desktop database (builder to verify pgvector support in PGlite or guard
  the index).

## Contracts (sketch — final shapes are the planner's call)

```

POST   /memories                   body: MemoryInput (+ finding_id?)  → Memory
POST   /memories/:id/merge         body: { content, source }          → Memory
GET    /memories?repo_id&scope&kind&stale&archived&q                  → { items: Memory[], counts, search_mode }
GET    /memories/similar?content&repo_id                              → MemorySummary[]
PATCH  /memories/:id               body: Partial<MemoryInput> | { archived: boolean }
DELETE /memories/:id
```
